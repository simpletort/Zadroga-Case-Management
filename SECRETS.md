# Secret Manager Inventory

Generated by reading the codebase for every reference to `gcloud secrets`,
`--set-secrets`, `secretmanager.SecretManagerServiceClient`, and equivalent
Secret Manager wiring. This is a point-in-time inventory, not a source of
truth — treat `openapi.yaml` / service `config.py` files as authoritative if
they disagree with this doc.

> Per [CLAUDE.md](CLAUDE.md): never hardcode GCP project IDs, Cloud Run URLs,
> or service account keys. All secrets below must be created in Secret
> Manager and injected via `--set-secrets` / env var — never committed to
> the repo.

## Discrepancies worth flagging

- **`services/lead-intake` secret list is stale.** `services/lead-intake/api/config.py` explicitly states lead-intake has *no* SendGrid/Twilio fields — "All messaging (SMS, email) is handled by the notification service." But `services/lead-intake/SETUP_AND_TESTING.md` and `services/lead-intake/cloudbuild.yaml`-adjacent docs still reference `sendgrid-api-key`, `twilio-account-sid`, `twilio-auth-token`, `twilio-from-number` as lead-intake secrets. Confirm whether that doc is outdated before provisioning those four under lead-intake's service account.
- **SendGrid secret naming is inconsistent**: `sendgrid-api-key` (lowercase-hyphen, lead-intake docs) vs. `SENDGRID_API_KEY` (uppercase, intake-form-dispatcher and enrollment-workflow). Pick one convention and reconcile, since Secret Manager names are case-sensitive.
- **Twilio secrets exist under two different names** depending on service: lead-intake's setup doc uses lowercase-hyphenated names (`twilio-account-sid`), while `services/notification` (the service that actually owns SMS/Twilio per current code) uses uppercase underscore names (`TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`) in both its `cloudbuild.yaml` and `infrastructure/notification-setup.sh`. Treat the notification-service names as current/authoritative since that service is the one Cloud Build actually deploys with `--set-secrets`.
- No `cloudbuild.yaml` was found for: `auth-rbac-cr`, `case-development`, `reporting-service`, `storage-gateway`, `task-management`, `workflow-orchestrator`, `settlement-financial`, `revenue-analytics`, `enrollment-workflow` that wires any `--set-secrets`. These services either don't require Secret Manager secrets today, or their deploy pipelines are incomplete/pending.
- Per [CLAUDE.md](CLAUDE.md), `revenue-analytics` is a skeleton service — its `cloudbuild.yaml` exists but should not be treated as evidence of a live secret requirement.
